# Rulegen

A working sketch-to-creative-code studio powered by p5.js and the OpenAI Responses API.

## Run

Use Node.js 22.16+ (Node 24 LTS recommended).

```sh
npm install
npm run dev
```

Create `.env.local` at the project root:

```dotenv
OPENAI_API_KEY=your_key_here
OPENAI_MODEL=your_image_capable_model
```

The app honors `OPENAI_MODEL`. The model must support image input and structured JSON output via the Responses API. Environment files are loaded only by the server. Restart after changing configuration. No API keys enter browser bundles or project exports.

## AI generation logs

Every AI generation (extraction, transformation and state-machine generation, clarification, revision proposals, code, composition prompt drafting and sketch composition, including retries/repairs) is automatically saved on the server under `ai-generations/<UTC date>/<timestamp-intent-unique ID>/`. Each folder contains `log.json` with model, status, timestamps, duration, request ID and token usage when returned; `request.json` with the app input; `prompt.json` with the AI request body; `response.json` (or `response.txt` for non-JSON responses); and `result.json` with the validated result. Code results also include `generated.js`. Input images are saved as `image-*.png/jpg/webp`, referenced by relative filenames in the JSON logs. Failed and cancelled requests include `error.json`; requests interrupted by a server shutdown retain `started` status. A file appears only once its corresponding stage has been reached.

Open **AI history** in the header to browse every generation, inspect successful results or errors, download the result log, and restore a completed generation without another AI call. New generations also save `context.json` (the project before generation, target sketch, selection region and annotation draft) and `recovery.json` (the restorable project plus clarification/proposal data) alongside image assets. Restore replaces the current local draft with that generation's project; export any draft you want to keep first. Unconfirmed revision proposals restore for review rather than being applied automatically. Logs from previous project formats are not restored.

Transient OpenAI failures (503 overload, 500/502/504, rate-limit 429) are retried up to 3 times with backoff (2s, 4s, 8s, or the server's Retry-After); exhausted quota and key/model errors are not. Retried responses are kept as `response-<round>-retry<n>.txt` and listed under `retries` in `log.json`.

**Error logs.** Every error the studio shows is also written to `error-logs/<UTC date>/<timestamp-source-id>.json`: `ai` (failed generations with intent, model, HTTP status, provider error code and the `ai-generations/` key), `prepare` (code that failed the safety check, with the code), `runtime` (errors thrown by a generated sketch in the browser, with its program), `ui` (other errors shown on a frame) and `server` (malformed requests). API keys are redacted and image data URLs omitted. Set `RULEGEN_ERROR_LOG_DIR` to change the folder; it is excluded from Git.

Logs are local files excluded from Git, and do not include authorization headers or API keys. They are retained until you remove them. Set `RULEGEN_AI_LOG_DIR` in `.env.local` to change the destination (relative paths resolve from the project root). If the server cannot write logs, generation reports a storage error. Local actions such as Make pen, widget edits and running existing code do not invoke AI and do not create generation logs.

## Workflow

1. Use **Add sketch frame (+)** in the left toolbar to add an independent sketch canvas. Click/draw on a frame to edit it; Undo, Redo and Clear apply to that frame. Use its Extract button to find collections and objects there. Use the trash button in each frame header to delete it. Deleting a sketch also removes its generated result, panel and drawing history; deleting an extracted frame keeps its source sketch. The original sketch can also be deleted; Add sketch frame restores an empty sketch when needed. Deleting the brush playground clears its test marks and closes the Brush step; opening Brush shows it again. Frame deletions persist in local saves and JSON exports. Additional frames, artwork and positions are included in local saves and JSON exports. Draw with the pencil, erase, undo/redo, pan with H or Alt+drag, and zoom using the left toolbar. Pencil settings open beside the pencil button.
2. Attach a PNG, JPG, or WebP photo (up to 20 MB), drop it on the canvas, or paste a copied image/screenshot with Cmd+V / Ctrl+V while outside text fields. Photos are resized locally before use and pasted/attached into the selected sketch frame. Click a sketch frame, its header, or its Focus button to select it; a green border and highlighted title show the active destination. Pasting can be undone/redone independently in that frame. You can sketch over a photo.
3. **Extract** the whole image, or draw a closed lasso with L to extract only that region, into a new frame beside it. The AI returns a scene of **collections** (groups that carry a semantic transformation applied to all members) and **objects** (basic primitives), nested as needed, plus a reusable **algorithm library**.
4. Use the **Layers** panel (left of the canvas) or the **Select** tool (V) on the sketch to select, rename, hide, group (⌘G), ungroup (⇧⌘G), nest (drag in Layers), reorder, move (drag / arrow keys) or delete nodes. Clicking selects the outer collection first, clicking again goes one level deeper. Layer edits have their own Undo/Redo.
5. The right panel (no tabs) shows the selected node's **stack of semantic transformations** (up to 6 per node, applied top to bottom; add one blank or with AI, rename, reorder with ↑↓, regenerate or delete each). Property ids are unique per node, so live keys stay `nodeId/propertyId`. Each property is a **socket** (spatial, stylistic or temporal) holding a value or an **algorithm block**. Blocks are independent of properties: drag one from the **block palette** (or from another socket) into any number/block socket, right-click a block to **Copy block** and right-click any socket to **Paste** it (the clipboard works across sketches), swap a socket's block from its menu, or drop a block on the empty socket to add a property. Block arguments are sockets too, so blocks nest. Editing a block's definition in the palette updates every place it is plugged in. Regenerate one property or the whole transformation with AI. Drag a layer from **Layers** onto another frame to copy it there with its members, blocks and machines: the result is generated and drawn inside that frame. Moving nodes within a frame moves the running result with them, live while you drag.
6. Generate p5.js code from the scene. Every scalar (including nested algorithm arguments) and each node's position, size and visibility are linked, so sliders and layer moves update the result without another AI call. Code shows in the bottom **Raw p5.js** panel: edit and run it there, copy or download it, or ask AI to fix a runtime error.
7. Click **Annotate** above the generated result and sketch freely over it. Click **AI clarification 만들기** to let AI compare the clean result with your sketch and fill an editable **Text clarification** draft. Review or edit the draft, then request rule/visual-feature suggestions. Use **AI 설명 다시 만들기** to reinterpret an updated sketch. Review concrete Before/After changes to collections, objects, properties and algorithms, then **Confirm** to regenerate connected p5.js code and apply them together. Use **Erase** (or E), **Undo/Redo**, Cmd/Ctrl+Z, Cmd/Ctrl+Shift+Z or Ctrl+Y to edit the sketch; Clear preserves the underlying generated result and clarification. Editing the sketch or clarification invalidates older suggestions. Cancel or generation failure keeps the current result. Feedback sketches are temporary; confirmed changes persist with the project.
8. Right-click a block (or use the palette) and choose **Make pen** to add a colored pencil carrying the algorithm call, its exact arguments and every definition it depends on. This is immediate and does not call AI. Draw freely with it just as with Pencil: the canvas keeps ordinary lines, each tagged with the pen's semantic meaning. Switch between pens and Pencil to sketch a composition. Compose first builds a collection scene that reuses the pens' algorithms by id, then generates its code. Click **Compose sketch** with an empty **Compose prompt** to have AI recognize the full sketch and fill an editable Korean prompt first. Review or edit it, then click **Compose sketch** again to generate the result. **AI prompt 만들기 / AI prompt 다시 만들기** can also draft or refresh the prompt, taking existing text into account. Prompt drafting needs no prior feature analysis and uses the image plus stored stroke semantics; edits made during a request are preserved. Drafting is logged alongside other AI requests. AI receives the full sketch image, ordered paths (including erasers), per-stroke algorithm snapshots and the prompt to create the selected sketch's generated result. Pen colors identify semantics; the prompt and drawn forms determine the output. For example, sketch an increasing pattern with a Power pen and ask for growth using its exponent along a Pencil layout. Click a toolbar pen to inspect or edit its meaning and color; changes affect future strokes. Removing a pen keeps the semantics on existing marks. Pens, stroke metadata and each sketch's Compose prompt persist in project JSON and local storage.

The current exploration, uploaded image, scenes, blocks and generated code persist in browser local storage (project format `version: 2`; earlier formats are not migrated). Export a `.rulegen.json` file before starting a new project to keep an independent copy. Imported JSON is validated. Storage quota failures are shown in the header; JSON export is still available.

Generated sketches run in an iframe with a separate sandbox, no app storage access, and no network permission. Code is parsed on the server and guarded against unbounded loops and recursion. The engine and p5 library are bundled locally; no CDN is required. Rendering errors are surfaced with an AI repair option.

## Verification

```sh
npm run typecheck
npm test
npm run build
npm start
```

Tests cover code execution guards, forbidden APIs, semantic pencil snapshots, prompt composition context, procedural-economy review and repair, semantic composition AI context, image request validation, and project serialization. Live API requests incur usage on the configured OpenAI account; no mock outputs are returned.

**One frame model.** There are no separate result frames: every frame is a sketch frame that renders its own generated result underneath its strokes and layer boxes, and you can keep sketching on it. **Extract** and **Compose** place the scene in a *new* frame beside the source sketch and render its result there; the source stays a plain sketch, and the new frame remembers where it came from (it warns when the source changes). Frame headers offer **Run/Pause** (animations and state machines), **Re-render**, **Generate/Update**, **Interact**, **Annotate** and **Extract**. **Interact** puts the frame in interaction mode: only the running result takes mouse, touch and keyboard input, while the frame's strokes, layer boxes, layer drops, scene shortcuts and image paste are switched off (leave with **Done** or Esc). The compose-prompt and compose prompts treat a form redrawn in another shape (pressed, hovered, dragged, before→after) as one node whose look changes with the interaction, not as extra collections. Value-only changes (sliders, layer moves, state values, timings) are pushed into the running sandbox and re-rendered in place; only program changes reload it, keeping the last image on screen meanwhile. Each frame keeps its own scene, selection, code draft, prompts and result in local storage and project JSON.


The toolbar includes a default **Interaction pen**, alongside algorithm pens. Use it to sketch click/tap targets, hover areas, drag directions and drop locations. Select it again to edit its meaning and color. Marks retain the meaning they had when drawn; the default pen and annotations persist in local storage, project exports and AI recovery snapshots. AI interprets them as user input annotations and generates actual p5 input callbacks, excluding the guide marks from the artwork. Compose prompt drafting, state planning and code generation all receive the annotated sketch and ordered stroke metadata.

State machines belong to individual **collections and objects**, not to the whole frame. Use **Generate state machine** on a node without one; each state changes only that node's property values (same structure as the base property). The bottom **State Machine** panel shows the selected node's graph with semantic transition labels, play/pause/restart and event buttons. Clicking a state jumps the preview there and switches the right **Properties** panel to that node with the state's values: slider edits then apply to that state only (**Base** edits the shared values), and the state's description and outgoing transitions are edited there too. Several nodes' machines run independently; generated code reads `rulegenState["node id"]` and emits `rulegenEmit("node id", "transition id")`; the prompts require both ids as string literals at every direct call (no wrapper helper or variable id), because the server checks them against the scene. Planning still separates meaningful input, motion, completion, cancellation and recovery phases, with up to **32 states and 128 transitions** per node. In the panel, drag the empty background or scroll to **pan** (double-click resets). Drag state boxes and transition labels to **move** them (a moved label bends its arrow to pass through it) (saved per frame and node; **Auto layout** restores the grid). Click a state or transition to **select** it, click the background to deselect; **Refine state / transition / machine** then opens a text box instead of running at once, showing the attached item as a chip (× detaches it to refine the whole machine). **Annotate** lets you draw on the graph; the strokes are attached too, and Refine sends the graph image (attached item in orange, annotation in coral) plus the items each stroke touches. The AI changes only what the request needs (`machine-refine` intent, `prompts/machine-refine.md`) and also rewrites the frame's **Compose prompt** bullets to describe the refined behavior; the source sketch's prompt follows when it is the same prompt.

## Prompts

All AI prompts live in [`prompts/`](prompts/) as Markdown, one file per intent (`extract`, `compose`, `transform`, `state-machine`, `code`, `compose-prompt`, `clarification`, `revision`), with shared contracts in `prompts/contracts/` pulled in through `{{include:…}}`. Each file ends with its output JSON format, and `prompts/schemas/<intent>.json` holds the exact strict JSON Schema the server sends. Prompts are re-read on every request, so edits apply without a restart. After changing a schema run `npm run prompts:schemas` (tests fail when the files are stale). `RULEGEN_PROMPT_DIR` changes the location.

**Structure and granularity.** Parts that share a clear common feature (same primitive, look or behavior) stay ONE whole object, their differences expressed as fine-grained transformations; only parts that differ in kind become nested collections (whole → part groups → parts, up to 5 levels; deeper model output is flattened to level 5 and layer edits beyond it are refused). Transformations are split as finely as possible: each is ONE semantic operation named for what it does ("Radial bloom", "Petal size falloff", "Wind sway"), usually 1–3 properties, never an effect-type bucket like "Spatial" / "Style" / "Temporal" (up to 12 per node). These rules are given to the model through the prompts only; the server does not check them (the former checks are kept in `backup/server-checks/`).

**Create Minimal Example.** Every semantic transformation card has a **Create Minimal Example** button. It adds an ordinary sketch frame beside the current one holding just one collection and one object with only that transformation (a collection's transformation acts on one plain member object; an object's transformation sits on the object inside a plain collection), without state machines and with only the algorithms it uses, then renders it so the transformation can be tried and its sliders tested on their own.

**Procedural economy.** Extraction, Compose and revisions describe repeated elements (petals, dots, leaves, rows, scattered marks …) as ONE node whose semantic transformation generates the instances: a count, a layout block (row/grid/radial/scatter/along-path/recursive) and algorithmic per-instance variation. Generated code draws every instance inside the node's box.
