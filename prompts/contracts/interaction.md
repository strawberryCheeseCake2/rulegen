## INTERACTION ANNOTATION CONTRACT

`compositionPens` with `kind: "interaction"` and `compositionStrokes` with `tool: "interaction"` are user-interaction annotations. Interpret their stored meaning, ordered geometry, proximity to the ordinary sketch and the user instruction as input targets, hover/hit areas, click/tap markers, drag trajectories, drop destinations or keyboard-driven responses. They are not artwork, algorithm-bearing geometry, output colors or a literal path to paint. Honor erasers and the CURRENT visible sketch. Preserve the distinction between the intended user's gesture and an object's autonomous animation. A gesture must remain driven by actual user input; do not replace clicking or dragging with a timed demo.

- For prompt drafting: explain the inferred interaction plainly in Korean, including its target, action, response and termination/cancellation if shown. Marks near the target can be alternate drawings of that target's look during or after the interaction (e.g. a stretched, opened or recolored version): describe them as the target's changed appearance in that phase, not as additional elements.
- For scene extraction/composition: attach the interaction to the node that is the input target and give that node a detailed machine.
- For state planning: split the interaction into detailed phases and name the transitions by their semantic action or completion condition.
- For generated p5 code: implement the input in the target node's module with its input handlers (`mouseMoved`, `mousePressed`, `mouseDragged`, `mouseReleased`, `touchStarted`/`touchMoved`/`touchEnded`, `keyPressed`/`keyReleased`) using canvas coordinates (`p.mouseX`, `p.mouseY`) and hit tests against the node's geometry inside `m.box(...)`. Every module receives every input, so a module must only react when the input concerns its own nodes. Emit the correct transition with a direct `m.emit("node id", "transition id")` call with both ids as string literals (never through a wrapper function or a variable id) only when that node is in the transition's source state (`m.state("node id").id`) and the semantic condition holds. Support release/cancellation/re-entry when described. Keep annotation marks out of the rendered result.
